## 1. 프로젝트 개요

### 과제명

**응급 환자 골든타임 사수를 위한 지역 병원 병상 및 이동 동선 통합 제어**

### 팀과 역할

국립한국교통대학교 컴퓨터소프트웨어학과 캡스톤 디자인 G팀

| 담당 | 역할 |
|---|---|
| 유익 | AI 및 데이터 파이프라인 |
| 최상은 | React 프론트엔드 |
| 오제영 | Python/FastAPI 백엔드 |
| 김도현 | Flutter 모바일 |

### 최종 목표

환자의 현장 정보와 병원 운영 정보를 결합해 다음을 지원하는 프로토타입을 만든다.

1. 상처 이미지에서 상처 외관 유형을 분류한다.
2. 구급대원의 추가 입력 부담 없이 확보 가능한 정보와 상처 이미지로 **연구용 중증도 위험 예측**을 수행한다.
3. 예측 결과, 필요 자원, 병상/수용 가능성, ETA를 결합해 Top-3 병원을 추천하고 상태 변경 시 재라우팅한다.

### 절대 지켜야 할 경계

현재 프로토타입은 임상 의사결정 지원 연구용 데모이며, 진단·KTAS 확정·실제 이송
결정을 대체하지 않는다. 의료 책임은 자격을 갖춘 구급대원 및 의료진에게 있다.

## 2. 현재 AI 구현 상태

### 2.1 상처 이미지 분류

- 데이터 흐름: Roboflow COCO export → bbox crop → EfficientNet-B0 backbone + MLP head
- 클래스: `abrasions`, `bruises`, `cut`, `stab`
- 입력: 224×224, ImageNet 정규화
- train augmentation: horizontal flip, ±15° rotation, color jitter
- validation/test: 결정적 resize + normalize
- checkpoint: `dataset/best_efficientnet_b0_wound.pt`

저장된 내부 결과는 validation accuracy **0.9661**, hold-out test 31 crop에서
accuracy/macro-F1/balanced accuracy **1.000**이다.

| Test class | 지원 수 | F1 |
|---|---:|---:|
| abrasions | 11 | 1.000 |
| bruises | 11 | 1.000 |
| cut | 6 | 1.000 |
| stab | 3 | 1.000 |
| 전체 | 31 | 1.000 |

### 2.2 분류 결과의 해석 한계

위 결과를 실제 성능으로 과장하면 안 된다.

- test 표본이 31 crop뿐이고 `stab`은 3건이므로 신뢰구간이 넓다.
- train crop 수보다 독립 원본 이미지 수가 훨씬 적으며, 환자/사례 ID가 없다.
- 파일명 기준 train/valid/test의 동일한 Roboflow pre-augmentation 키 중복은 발견되지 않았지만, 동일 환자·촬영 세션·유사 프레임의 누수는 배제할 수 없다.
- 이 모델은 **상처 유형 분류기**이지 중증도, KTAS 또는 진단 모델이 아니다.

발표 권장 문구:

> 내부 hold-out test 31 crop에서 macro-F1 1.000을 기록했으나, 소규모·불균형 test set 및 환자 단위 분할 부재로 일반화 성능은 확정할 수 없다.

## 3. 중증도 설계 원칙

### 3.1 금지된 설계

다음과 같은 고정 매핑은 임상적 근거가 없으므로 금지한다.

```text
stab -> KTAS 1
cut -> KTAS 2
bruises -> KTAS 4
```

동일한 상처 유형도 활동성 출혈, 의식 상태, 호흡·혈역학 상태, 통증, 해부학적 부위,
손상기전에 따라 서로 다른 중증도를 가질 수 있다.

### 3.2 현재 가능한 연구용 구조

```text
상처 이미지
  -> EfficientNet-B0
  -> 상처 유형 확률 / 영상 embedding

기존 구급 업무/장비에서 이미 획득한 정보(향후 연동)
  -> 위치·시각, 활력징후, 의식, 출혈 여부, 손상기전
  -> 연구용 중증도 위험 예측 또는 향후 임상 검토 KTAS 라벨

중증도 + 필요 자원 + 병상/수용 가능성 + ETA
  -> Top-3 병원 추천 + 병원 전송 프로토콜 + 재라우팅
```

별도의 긴 시나리오 입력 화면을 구급대원에게 요구하지 않는다. 현재 데모에서는
시나리오 값이 라우팅 알고리즘의 내부 테스트/평가 입력으로만 존재한다. 실사용을
가정할 때는 기존 구급활동기록(ePCR)·장비·관제 시스템에서 이미 수집하는 값의 연동을
우선하며, 새로 요구할 수 있는 입력은 `의식 이상`, `조절되지 않는 출혈` 같은 1-tap
확인 수준으로 제한한다.

임상 검토자 및 적절한 라벨 데이터가 없는 현재 단계에서는 이미지 단독 결과를
**KTAS 확정값**으로 표시하지 않는다. 누락된 임상 정보가 있을 때에는 위험을 낮게
추정하지 말고 `정보 부족 - 구급대원/의료진 확인 필요` 상태와 모델 불확실성을 병원에
전송한다.

### 3.3 병원 전송 프로토콜

추천 병원에는 예측 결과만 보내지 않고, 병원 전 사전 수용 판단에 필요한 최소
프로토콜을 함께 전송한다.

```text
case_id(비식별) / 촬영·전송 시각 / 현재 위치
상처 유형 예측과 신뢰도 / 중증도 위험 예측과 불확실성
연동된 활력징후·의식·출혈 상태와 각 값의 갱신 시각
필요 자원 후보 / 추천 병원 Top-3 / ETA
누락 정보 / 최종 의료진 확인 필요 표시
```

이 프로토콜은 실제 EMR·119·병원 API 연동 전까지는 데모용 schema이며, 개인식별정보나
환자 영상은 동의와 보안 체계 없이 전송하지 않는다.

### 3.4 KTAS 라벨링 준비 상태

`dataset/triage_manifest.csv`가 생성되어 있으며 1,632 crop에 기존 상처 유형 라벨만 채워져 있다.

| 상처 유형 | 수 |
|---|---:|
| abrasions | 573 |
| bruises | 839 |
| cut | 124 |
| stab | 96 |
| 합계 | 1,632 |

`clinical_ktas_level`은 의도적으로 비어 있다. 임상 검토자가 아래를 확인한 뒤에만 입력한다.

- 비식별 case ID, 주호소, 손상기전, 부위, 통증
- 의식·호흡·혈역학 상태, 활동성 출혈 및 지혈 여부
- KTAS 근거 코드, 검토자 역할/ID, 검토 시각

현 상태에서 KTAS 라벨 수는 **0건**이다. 임상 입력과 자격 있는 검토자 확인이 없는 이미지에 KTAS를 자동 부여하지 않는다.

## 4. 데이터 확보 전략과 제약

### 4.1 IRB/임상 자문 없이 가능한 범위

공개 상처 이미지 데이터는 EfficientNet-B0의 상처 탐지·분류·segmentation 실험에는 사용할 수 있다. 예시는 CO2Wounds-V2, 공개 라이선스 Roboflow wound 데이터셋이다.

그러나 공개 상처 이미지 데이터에는 한국 KTAS 정답이 없으므로, 이를 이용해 한국 응급환자의 중증도 예측 성능을 주장할 수 없다.

### 4.2 한국 중증도 데이터 후보

- 질병관리청 **응급실손상환자심층조사** 원시자료: 손상 관련 구조화 정보와 최초/최종 KTAS, ISS 등을 포함하는 후보다. 신청서와 심의가 필요하며 사진 데이터는 아니다.
- AI Hub **응급실 임상 대화 데이터**: KTAS 라벨이 포함된 한국어 음성/전사 데이터다. KTAS 3-5에 편중되어 있고 이미지 데이터가 아니며, 안심존 이용 조건을 확인해야 한다.
- AI Hub **단계별 욕창 이미지**: 한국 의료 이미지이지만 욕창 단계 라벨이며 급성 외상 또는 KTAS 데이터가 아니다. 안심존/IRB 조건이 붙을 수 있다.

따라서 사진과 KTAS가 동일 case ID로 연결된 임상 데이터가 확보되기 전까지 image+KTAS fusion 모델을 학습하지 않는다.

## 5. 동적 병원 라우팅 설계

### 5.1 입력과 출력

입력:

- 환자 위치
- 상처 유형/중증도 위험 예측 및 불확실성
- 기존 구급 업무 또는 장비에서 연동된 최소 상태 정보와 각 갱신 시각
- 필요 자원 집합
- 병원별 병상·서비스 가용 상태와 마지막 갱신 시각
- OSM/ITS 기반 ETA(현재는 시뮬레이션 placeholder)

출력:

- Top-3 병원 및 각 추천 근거
- ETA, 예상 대기, 수용 가능성, 자원 충족 여부
- 상태 변경 또는 거절 시 재라우팅 결과
- 병원 사전 전송 프로토콜, 누락 정보, 데이터 갱신 시각, 최종 의료진 확인 필요 고지

### 5.2 비용 함수

```text
J(h) = ETA(h)
     + alpha * E[wait(h)]
     + beta  * (1 - P_accept(h | scenario))
     + gamma * P(required resource unavailable | h)
```

- `alpha`: 대기시간의 분 단위 등가 비용
- `beta`: 수용 거절 위험 패널티
- `gamma`: 필요 자원 불가 위험 패널티

`beta`, `gamma`, 병상 가용성 확률, ETA 보정계수는 임상적 사실이 아니라 현재 **시뮬레이션 가정**이다. 상수는 코드에 하드코딩하지 말고 config로 공개한다.

### 5.3 현재 라우팅 구현

`emergency_cdss/scripts/routing_sim.py`에는 아래 기능이 있다.

- `nearest`, `max_beds`, `proposed` 정책 비교
- 공통 환자·병원 상태 난수를 공유하는 paired 비교
- beta/gamma 그리드 민감도 분석
- proposed - baseline에 대한 paired bootstrap 95% 신뢰구간
- 정책 요약 CSV, 민감도 CSV, bootstrap JSON 출력

이 결과는 합성 시나리오 성능이므로 실제 이송시간·수용률의 효과로 해석하지 않는다.

## 6. 안전성과 발표 표현

### 말할 수 있는 것

- 공개 상처 이미지에 대한 상처 외관 유형 분류 프로토타입을 구현했다.
- 예측 결과·필요 자원·ETA·병상 상태를 결합한 병원 추천 알고리즘을 시뮬레이션으로 비교할 수 있다.
- 불확실성, 병상 갱신 시각, 추천 근거, 재라우팅을 UI에 노출하는 설계를 제안했다.

### 말하면 안 되는 것

- 이미지 한 장으로 KTAS를 진단하거나 확정한다.
- 실제 구급 이송 시간을 단축하거나 사망률을 개선했다.
- 합성 라우팅 결과가 실제 병원 운영에서 검증되었다.
- 상처 유형 분류 성능 1.000이 실제 임상 일반화 성능을 보장한다.

## 7. 현재 우선순위

1. **P0 - 데모 완성**: 상처 유형/중증도 위험 예측 결과, Top-3 라우팅, 병원 전송 프로토콜, 추천 근거 및 재라우팅 화면을 연결한다. 별도의 긴 시나리오 입력 화면은 만들지 않는다.
2. **P0 - 평가 정직성**: patient/case ID 부재, 소규모 test set, 합성 라우팅 가정을 발표 자료에 명시한다.
3. **P1 - 라우팅 검증**: beta/gamma 민감도 분석과 paired bootstrap 신뢰구간을 결과표에 포함한다.
4. **P1 - 실제 데이터 조사**: 지도교수/학교 규정상 면제 확인 또는 질병관리청 원시자료 신청 가능성을 확인한다.
5. **P2 - 임상 라벨 확보 후**: case-level split, 이중 라벨링, calibration, KTAS 1-2 recall, under-triage 비율을 포함해 중증도 모델을 별도 검증한다.
